2 PostgreSQL Database Architecture & Data Storage

All structured relational data is stored in PostgreSQL running in a dedicated, isolated Docker container on the VPS.

Container & Network Specifications

  • Container Name: library_postgres
  • Docker Image: postgres:16-alpine
  • Database Name: library_db
  • DB User: library_user
  • Internal Port: 5432 (Closed to external internet)

Host Storage Volume Mapping

  • Docker Named Volume: postgres_data
  • Physical VPS Host Path:
    /var/lib/docker/volumes/kil-library_postgres_data/_data/
  • Persistence: Data survives container restarts, rebuilds, and system reboots.

Tables & Data Models Stored in PostgreSQL:

Module Tables / Entities Stored Purpose
User & Auth users, roles, permissions, role_permissions Login accounts, passwords, staff assignments, audit tracking
Library Catalog books, book_copies, categories, subcategories, authors, publishers, languages, locations Complete metadata for physical and digital books, volume info, barcode tracking
Circulation book_issues, requests, book_permissions, book_orders Borrowing records, student access requests, physical copy issuance
Community & Content fatawa, social_work, newspaper_clippings, posters, gallery_items, comments Islamic inquiries, charitable activities, event archives, media clips
System Logs logs, token_blacklist Audit trail of user actions, login attempts, revoked tokens

Database Backup & Restore Commands:

# Create instant SQL backup dump on VPS:
docker compose exec -T db pg_dump -U library_user library_db > /root/backup_$(date +%Y%m%d).sql

# Restore SQL backup:
cat /root/backup.sql | docker compose exec -T db psql -U library_user -d library_db

3 Multi-Tier Media & File Storage (PDFs, Images & Books)

To support 10,000+ books and high-resolution PDFs without overwhelming the VPS disk, the backend features an intelligent 3-tier storage hierarchy:

Storage Tier Destination Content Handled Cost & Scaling Benefit
Tier 1: Cloudflare R2 (Primary) Cloudflare S3-Compatible Object Bucket Heavy Book PDFs, scanned manuscripts, digital library documents Zero Egress Fees. Millions of downloads with no bandwidth penalty.
Tier 2: Cloudinary (Secondary) Cloudinary Account (dhlfaiijj) Book cover thumbnails, event posters, author photos, gallery media Automatic WebP/AVIF transformation, dynamic resizing, global edge CDN.
Tier 3: VPS Disk (Local Fallback) /app/static/uploads
Host: /root/kil-library/library_backend/static/uploads/		 Uploaded assets when external cloud keys are absent or during offline testing Direct volume mount in Docker via backend_uploads volume.

Smart Conditional PDF Optimization Engine:

Lossless Rule: Files ≤ 100 MB are kept 100% untouched to preserve pristine text/vector clarity. Files > 100 MB undergo automatic progressive stream compression before cloud upload, then local temp files are purged.

6 Production Quick Maintenance Cheat Sheet

# 1. Check all live container statuses:
docker compose ps

# 2. View real-time backend application logs:
docker compose logs -f backend

# 3. Restart entire stack cleanly:
docker compose down && docker compose up -d

# 4. Force Super Admin reset:
docker compose exec backend python setup_admin.py

# 5. Check database connection inside container:
docker compose exec db pg_isready -U library_user -d library_db
